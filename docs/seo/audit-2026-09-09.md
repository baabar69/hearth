## The two questions the founder asked

### 1. "dear hearth" is autocorrected to "dear heart"

There is no setting for this; it is Google's spelling model. "dear heart" is a common phrase with real query volume; "dear hearth" has none (Google autocomplete returns zero suggestions for it, and the Aug 21 Search Console data showed no brand impressions at all). When a rare query is one letter from a common one, Google assumes a typo and shows "Showing results for dear heart". It stops doing that when the rare query proves itself: people search it and click "Search instead for dear hearth" often enough, and the web contains the exact string as an entity name.

What moves it, in order of effect:
1. **Make "Dear Hearth" the entity name Google sees.** Today the Organization schema says name "Hearth", alternateName "Dear Hearth", and the WebSite name is "Hearth", so Google's site-name feature and Knowledge Graph learn "Hearth", a common noun we can never own. Swap them: Organization name "Dear Hearth", alternateName "Hearth"; WebSite name "Dear Hearth"; og:site_name "Dear Hearth"; title suffix "· Dear Hearth". This is the single most direct fix, and it is a small change in app/layout.tsx.
2. **Point sameAs at every profile that spells it "Dear Hearth".** Add Instagram (instagram.com/thedearhearth) and Threads; check that the LinkedIn and Crunchbase profile names read "Dear Hearth", not "Hearth".
3. **Get the string onto other sites.** The link-building doc's directory and profile list, each using "Dear Hearth" as the name. Every external mention of the exact string teaches the spelling model it is a name.
4. **Create the demand.** Instagram bio, captions and any ad say "Dear Hearth"; the phrase people search is the phrase they see. Branded searches plus clicks on "search instead for" are the training signal. This is the slow part and there is no shortcut.
5. Bing: set the site name in Bing Webmaster Tools to "Dear Hearth" (Bing honours it directly).

### 2. Not ranking for "affordable therapy", "cheap therapy", "better than therapy"

Measured today with Google autocomplete:
- **"better than therapy"** is a Waterparks song. Every suggestion is lyrics, chords, or the band. Nobody searching it wants a service. Drop the term.
- **"affordable therapy" and "cheap therapy"** suggest "near me", "without insurance", "no insurance", "online", "options", "sessions". These people want therapy, priced low. Hearth is not therapy, and the founder's own positioning rule (2026-08-23) forbids selling on "cheaper". A page built to catch these would attract the wrong intent and contradict the brand. The head terms are also owned by Open Path Collective, BetterHelp, Psychology Today and health publishers; a four-month-old domain with near-zero backlinks does not rank for them regardless of content.
- **What is winnable, and already half built:** the informational tail. The site has /learn/cant-afford-therapy, /learn/how-much-does-therapy-cost, /learn/therapy-without-insurance, /learn/sliding-scale-therapy and /learn/do-i-need-therapy, all published within the last three weeks. Pages that age take two to four months to earn impressions. Autocomplete shows the exact phrasings to align them to: "can't afford therapy but need it", "can't afford therapy what do I do", "do I need therapy or am I overreacting", "do I need therapy quiz", "someone to talk to online", "someone to talk to right now", "affordable therapy without insurance", "online therapy alternative to betterhelp" (our /hearth-vs-betterhelp page). Each of these deserves either a matching H2 on the existing page or its own short page.
- **The real bottleneck is authority, not content.** The Aug 21 diagnosis stands: almost nothing links to dearhearth.com. Until the link-building plan produces a few dozen real referring domains, rankings for competitive terms will not move. Content without links is a library nobody can find.

## Fixes, in priority order

1. Brand entity swap in app/layout.tsx: Organization name "Dear Hearth" (alternateName "Hearth"), WebSite name "Dear Hearth", og:site_name, title suffix; add Instagram and Threads to sameAs. One file.
2. Security headers via `headers()` in next.config.ts (CSP, X-Frame-Options SAMEORIGIN, Referrer-Policy, Permissions-Policy, HSTS with preload), then remove the dead block from netlify.toml.
3. Fonts through `next/font` (self-hosted, preloaded) instead of three link tags; expected to cut FCP by 1 to 2 s on mobile. Then audit client JavaScript on the home page.
4. Placeholder Keeper pages: noindex the five /keepers/<slug> pages and drop Person schema until real hires exist (KAN-56), or keep them out of the sitemap. Fictional Person markup is a structured-data policy risk.
5. Trim the 35 long descriptions and 6 long titles.
6. Align the five learn pages to the autocomplete phrasings above (H2s and intros); add "someone to talk to online, right now" as a page if it does not exist.
7. Run the Search Console script and let the numbers, not the wish list, pick the next target.

Fixes 1 to 5 are code changes to app/ and config; per the standing rule they are drafted for review and committed only on approval. Fix 6 is copy. Nothing here creates a new public URL, so no indexing requests are needed yet.
